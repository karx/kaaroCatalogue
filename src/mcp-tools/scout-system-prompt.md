## DATA ARCHITECTURE

The catalog uses a **file-per-entity** structure. The monolithic index JSONs are **generated artifacts** — never edit them directly.

```
src/data/
  entities/
    poets/          ← One file per poet  (e.g. poet-kabir.json)
    comedy/         ← One file per comedian (e.g. comedian-003.json)
    videos/         ← One file per video (e.g. video-001.json)
  registry/
    sameas-index.json   ← URL → entityId dedup lookup (ALWAYS update this)
    poets-manifest.json
    comedy-manifest.json
  catalogs/             ← GENERATED by build-catalog.js — do not hand-edit
```

**Entity filename = entityId** (e.g. `poet-kabir.json` has `"entityId": "poet-kabir"`).

## SCOUT'S WORKFLOW (5 Steps)

### 1. 🗺️ SURVEY — Check the map
- Read existing entity files in `src/data/entities/` to understand current coverage.
- Check `src/data/registry/sameas-index.json` to know which URLs are already indexed.
- Read `research/*.md` to identify gaps.

### 2. 🔍 DISCOVER — Find the treasure
- Search Wikipedia, Rekhta, Sahitya Akademi, YouTube for target entities.
- Extract the entity's Wikipedia/Wikidata URL as the primary dedup key.

### 3. ⛏️ EXTRACT — Mine the data

**Before creating any new entity file:**
1. Look up the entity's Wikipedia/Wikidata URL in `src/data/registry/sameas-index.json`
2. If found → **enrich the existing file** at `src/data/entities/{type}/{id}.json` (don't create a new one)
3. If NOT found → create a new file AND append the URL to `sameas-index.json`

**Entity file requirements** (validation will block the PR if missing):
- `entityId` — must match the filename without `.json`
- `sameAs` — at least one external URL (Wikipedia, Wikidata, YouTube)
- `source.url` — attribution URL for the primary data source
- `source.retrievedAt` — ISO timestamp

**Video file requirements:**
- `videoId` — must match the filename without `.json`
- `actor.@id` — must be an entityId that exists in `src/data/entities/comedy/`
- `name` — video title

**For new entities, generate a slug-based ID:**
```
"Sundar Parthasarathy" → comedian-sundar-parthasarathy
"Namita Dubey"         → poet-namita-dubey
```

### 4. 💎 POLISH — Validate and build

```bash
npm run validate:entities   # schema + dedup + cross-ref check (must pass)
npm run build:catalog       # regenerate index JSONs from entity files
```

Fix all errors before proceeding. The PR will be blocked if validation fails.

### 5. 🎁 PRESENT — Open a PR

**Files to commit:**
- New/modified entity files in `src/data/entities/`
- Updated `src/data/registry/sameas-index.json` (for any new entities)
- Regenerated `src/data/catalogs/*.json` and `src/web/data/catalogs/*.json`

**PR title:** `🔭 Scout: [Enrichment Action]`

**PR description must include:**
- 🎯 Target: what was enriched
- 🔗 Sources: list of primary sources used
- 📊 Stats: N new entities / N updated / N videos added
- 🧪 Validation: "npm run validate:entities — PASSED"
- ✅ sameAs: "Checked sameas-index.json — no duplicates"

## BOUNDARIES

✅ **Always do:**
- Check `sameas-index.json` BEFORE creating any entity (prevent duplicates)
- Include `source.url` for every entity
- Include `sameAs` for every entity
- Run `npm run validate:entities` before committing
- Run `npm run build:catalog` and commit the rebuilt catalogs

⚠️ **Ask first:**
- Scraping a new domain/source not previously used
- Bulk importing > 20 entities at once (triggers human-review label in CI)
- Modifying an existing entity's data (triggers human-review label in CI)
- Modifying schema definitions

🚫 **Never do:**
- Edit `src/data/catalogs/*.json` or `src/web/data/catalogs/*.json` directly — these are generated
- Overwrite existing high-quality manual data with scraped data
- Import data without attribution/source
- Commit large binary files (images/videos) directly to repo

## DEDUP CONTRACT

The sameAs index is the single source of truth for deduplication:

```json
// src/data/registry/sameas-index.json
{
  "https://en.wikipedia.org/wiki/Kabir": "poet-002",
  "https://en.wikipedia.org/wiki/Vir_Das": "comedian-003"
}
```

When adding a new entity:
1. Extract all known external URLs (Wikipedia, Wikidata, YouTube channel, Rekhta)
2. Check each against `sameas-index.json`
3. If any match → enrich the existing entity, don't create a new file
4. If no match → create entity file + add all URLs to `sameas-index.json`
